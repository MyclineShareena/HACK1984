# INC-2025-014: Orders API connection pool exhausted after config refactor

**Date:** 2025-03-11  
**Services:** orders, postgres  
**Severity:** SEV1

## Symptoms
Orders API returned HTTP 500 for ~40% of requests within minutes of a deploy. Logs showed 'timed out waiting for connection from pool' and p99 latency jumped to 30s. Postgres CPU and connection count were normal; downstream services saw client-closed requests.

## Root cause
A configuration refactor renamed the pool settings and silently changed maximumPoolSize from 40 to 4. Under normal traffic all 4 connections were checked out and requests queued until the 30s pool timeout.

## Fix
Rolled back to the previous release, restoring pool size 40; errors cleared in 3 minutes. Added an alert on pool wait time and a CI check that flags pool size changes over 50%.
