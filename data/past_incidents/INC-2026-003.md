# INC-2026-003: Payments DB connection leak exhausts Postgres pool under load

**Date:** 2026-02-02  
**Services:** payments, postgres  
**Severity:** SEV2

## Symptoms
Payments latency climbed steadily over two hours, followed by 'connection pool exhausted' errors and failed authorizations. Restarting pods fixed it temporarily.

## Root cause
An error path in the refund handler opened a transaction and never returned the connection to the pool. Leaked connections accumulated until the pool was empty.

## Fix
Mitigated by rolling restart. Fixed by wrapping DB sessions in a context manager, setting a pool leak-detection threshold, and graphing pool in_use / waiting per pod.
